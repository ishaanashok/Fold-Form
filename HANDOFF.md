## 1. What FoldForm is

A SwiftUI + RealityKit **iPhone Duo** (foldable, two-screen) CAD/sheet-metal modelling app. You sketch, extrude, cut, round, drill, and physically bend the design by folding the device; the hinge angle drives the bend.

- iOS 27.1 deployment target, **Swift 6 language mode (strict concurrency)**, iPhone portrait only.
- Xcode project is **generated by XcodeGen from `project.yml`**. Run `xcodegen generate` after adding/removing any file. Never hand-edit `FoldForm.xcodeproj`.
- Existing docs: `docs/README.md`, `docs/architecture.md`, `docs/features.md`, `docs/controls.md`, `docs/development.md`.

### Document model you must understand
- Bodies are mesh-backed features: `ViewportSolidFeature`, `ViewportCutFeature`, `ViewportTouchUpFeature`. Everything ends up as document bodies, so **folding, undo, autosave and export need no changes** when a new feature edits them.
- The **first body is the base plate** (`FoldSession.primaryID`); it cannot be deleted.
- Scene units are **metres**. World axes: x right, y up, z toward the viewer.
- `DesignScene.part(from:)` classifies a body as box / cylinder / other. `DesignPart.rebuilt(lo:hi:)` and `roundedMesh(radius:)` reshape it.
- `SketchController`: `begin`, `replaceShapes`, `startExtrude(cut:)`, `setDepth`, `confirmExtrude`. Extrude depth range is 0.002…0.15; minimum shape size 0.002.
- `AppModel.applyBodyEdit(_:label:)` replaces body meshes as one regenerated feature.
- `ViewportEntities` (`@MainActor`) owns the undo stack (`UndoSnapshot`, `push`, `restore`), redo, and `transact { … }`.

## 2. The product being built

Source-of-truth product spec: `~/Downloads/FOLDFORM_AI_HANDSFREE_SPEC.md` (outside the repo). The repo's narrower, reality-checked versions are:

- **Design spec:** `docs/superpowers/specs/2026-09-26-ai-handsfree-design.md`
- **Implementation plan (12 tasks):** `docs/superpowers/plans/2026-09-26-ai-handsfree.md`

Both are committed (`39ee460`). The user approved the design and chose **native inline execution with TDD**.

### Key features

1. **Hands-free voice control.**
   Live captions while speaking → on-device transcription (Moonshine Small Streaming, English) → interpreter (Needle 3 via Cactus, with a rule-based fallback) → validated CAD actions → executed against the document. Sessions stay listening after each command until stopped. Interim (still-changing) text is displayed but **never executes**; only a `FinalUtterance` can.
2. **Imagine mode** (sidebar). A sketch + voice/text description goes, on an **explicit Generate tap only**, to GLM-5.3-Flash on NVIDIA NIM (`https://integrate.api.nvidia.com/v1`, model `z-ai/glm-5.3-flash`). It returns a JSON feature plan applied as a **validated delta**. Stale replies are rejected; references are symbolic (`P0…Pn`, names).
3. **Shared CAD action layer** (`CADAction` → `CADActionExecutor`) used by both. One utterance / one plan = **one undo step**.
4. **Keychain credential storage**; no keys ever in Git.

### Decisions the user already made (do not re-litigate)
- Interpreter sits **behind a protocol with a rule-based fallback** (because Needle/Cactus integration is risky).
- Model files are **downloaded on first use** (not bundled).
- Documented deviations from the product spec: no face/edge selection (body-level only); `finish_sketch` discards unextruded shapes; rotating a body makes it non-resizable; chamfer is reported as unsupported; model-file manifest hashes are filled in when files are located, so the app says "not installed" until then.

## 3. Architecture (as built)

```
speech ─► FinalUtterance ─► CommandInterpreter ─► [ToolCall] ─► ToolCatalog.validateSequence ─► [CADAction] ─► CADActionExecutor
                                                                                                   run (voice, keeps partial)
                                                                                                   runAtomically (Imagine, all-or-nothing)
```

Files (all under `FoldForm/AI/`):

| File | Role |
|---|---|
| `Actions/Quantity.swift` | `Quantity.length/angle/isLengthUnit`, `SpokenNumber.parse`, `isNumberWord`. "three point five", cm/mm/in, "minus". |
| `Actions/CADAction.swift` | `ToolValue`, `ToolCall`, `Axis3`, `SizeMode`, `DimensionChange`, `ViewDirection`, `Displacement`, `BodyTarget`, `Placement`, `SelectionKind`, `ToolContext`, `ToolError`, `CADAction` (+ `summary`, rounded to 0.1 mm). |

| `Actions/CADActionExecutor.swift` | `@MainActor`. `run`, `runAtomically`, `currentContext()`. Handles create cube/box/cylinder/prism, sketch actions, resize, move, rotate, round, hole, duplicate, delete, undo/redo. Uses `viewport.transact` returning `.commit/.keep/.rollback`. |
| `Actions/MeshTransforms.swift` | `RenderMesh.rotated(by:about:)`. |
| `Voice/CommandInterpreter.swift` | `FinalUtterance(id:text:)`, `InterpretResult` (`.calls/.clarify/.needsImagine`), `protocol CommandInterpreter: Sendable`. |
| `Voice/RuleBasedInterpreter.swift` | Deterministic parser: normalises text, splits clauses, dispatches by intent. Clarifies ("Which direction?", "How far?", "Select a part first", "Nothing to do", "I didn't catch a command"); `.needsImagine` for creative words. |
| `Voice/SpeechService.swift` | `SpeechState`, `SpeechEvent`, `SpeechService`, `ScriptedSpeechService` (tests), `UnavailableSpeechService`. **Uncommitted.** |
| `Voice/VoiceCommandSession.swift` | `@MainActor ObservableObject`, `VoicePhase`. **Uncommitted.** |

Also modified for the AI work: `RealityViewport.swift` (redo, `transact`, `restore(_:endingSketch:)`, `select(documentBodyID:)`, `selectedDocumentBodyID`, `bodyCount`, `confirmExtrude(recordUndo:)`), `AppModel.swift` (`applyBodyEdit`), `DesignScene.swift` (`part(from:)` now internal).

### Behaviours worth knowing
- Transactions: rollback restores document, sketch and selection; a no-op rollback keeps the selection. Sketch-only requests add no undo entry (the sketch has its own undo).
- Atomic failure reports `completed = 0` and a single `.failed` result.
- Resize keeps the base for y and centre for x/z; cylinders stay round; rotated bodies refuse resize.
- Move uses the world axis nearest the camera direction. Hole axis = thin axis if the slab is thinner than 0.7× the next side, else the axis facing the camera.
- `selectionSubscription` is only installed in `setUp(in:)` (async, a Task per change). Unit tests never call it, so selection sync doesn't run in tests.
- Statics referencing `@MainActor` types are main-actor isolated in Swift 6, so the `extrudeRange` literal is duplicated and covered by an equality test.

### Review Focus (each must have a pinning test)
1. Interim speech text never executes an action — even if a stale final arrives late or twice.
2. "3" vs "30", "mm" vs "cm", "minus 10" vs "10": wrong sign/unit silently corrupts a design.
3. A plan failing at step 4 of 5 leaves the document exactly as before (no partial bodies, no undo entry).
4. A stale Imagine reply (document changed since request) is rejected.
5. A hostile/malformed GLM reply (huge counts, NaN, non-existent refs, `delete` of the plate) fails validation without touching the document.

## 7. How to build and test

Simulator: **iPhone Duo** (`platform=iOS Simulator,name=iPhone Duo`).

```bash
xcodegen generate
xcodebuild -project FoldForm.xcodeproj -scheme FoldForm \
  -destination 'platform=iOS Simulator,name=iPhone Duo' test \
  -only-testing:FoldFormTests/VoiceCommandSessionTests > /tmp/foldform_test.log 2>&1
grep -E "error:|Executed [0-9]+ tests|TEST (SUCCEEDED|FAILED)" /tmp/foldform_test.log | sort -u
```

Hard-won lessons:
- **xcodebuild can hang after test failures.** Run it in the background, poll the log for `** TEST SUCCEEDED/FAILED **` / `BUILD FAILED`, then kill *that* PID only. **Do not use broad `pkill`** — the user rejected that once.
- Log to a file and read only the tail/grep; the output is huge.
- macOS has no `timeout`; `sed -i` needs `''`. Use python for scripted edits.
- Full-suite totals: `grep "Test Suite 'All tests'" -A1 <log>`.
- Run `xcodegen generate` after adding files.
- **Don't hijack the emulator.** UI tests on the live simulator look like crashes / "no bend" to the user (see memory). Prefer unit tests; if the sim was disturbed, relaunch the app normally. Tests must not touch the network, mic, or live simulator UI.
